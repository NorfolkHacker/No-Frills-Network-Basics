Chapter 2 · Fundamentals

FundamentalsThe OSI model

Sending data across a network is a big job, so it's split into seven layers. Each layer does one job and only talks to the layers directly above and below it. When something breaks, the layers give you a checklist: is the cable plugged in (layer 1)? Do I have an IP address (layer 3)? Is the website up (layer 7)?

Think of posting a letter. You write it (application), put it in an envelope, write an address, and the postal service handles lorries and roads. You don't care which lorry carries it. Networks work the same way.

7
Application

What the user's program speaks. HTTP, DNS, SMTP, SMB.

6
Presentation

Formatting, encoding and encryption. Making data readable at both ends (e.g. TLS, character encoding).

5
Session

Opening, keeping and closing conversations between two programs.

4
Transport

TCP and UDP. Splits data into segments, uses port numbers to reach the right program.

3
Network

IP addresses and routing. Data travels as packets. Routers live here.

2
Data Link

MAC addresses, local delivery on one network. Data travels as frames. Switches live here.

1
Physical

Cables, fibre, radio waves. Raw 1s and 0s.

Remember the order from the bottom up with "Please Do Not Throw Sausage Pizza Away".

OSI vs TCP/IP

OSI is a teaching model. The internet actually runs on the simpler TCP/IP model, which squashes the layers into four: Link (OSI 1–2), Internet (3), Transport (4) and Application (5–7). People still say "layer 2" and "layer 7" all the time, so learn the OSI numbers.

A switch forwards traffic using MAC addresses. Which layer is that?

Layer 2, Data Link. Routers, which use IP addresses, are layer 3.

FundamentalsNetwork devices

A switch connects devices inside one network. A router connects different networks together, like your home to the internet. Your "broadband router" is actually several boxes squeezed into one.

DeviceLayerWhat it does
Hub1Repeats everything it receives out of every port. Dumb, noisy, mostly extinct. Everyone sees everyone's traffic.
Switch2Learns which MAC address is on which port and only sends frames where they need to go.
Router3Moves packets between networks using IP addresses and a routing table.
Access point2A switch port that uses radio instead of a cable. That's what Wi-Fi is.
Modem1Converts the signal on your phone line, cable or fibre into Ethernet. "MOdulator-DEModulator".
Firewall3–7Decides which traffic is allowed in and out. See Firewalls.

Your home router is usually a modem, router, switch, access point, firewall and DHCP server in one plastic box.

MAC addresses

Every network card has a MAC address, a 48-bit hardware ID written like 3c:22:fb:9a:10:4e. The first half identifies the manufacturer. MAC addresses only matter on the local network; they never cross a router.

try it · see your own addresses
# Linux / macOS
$ ip addr        # or: ifconfig
# Windows
> ipconfig /all
You plug two PCs into a switch. Do you need a router for them to talk?

No. If they're on the same network (same subnet), the switch is enough. You need a router to reach a different network.

FundamentalsTCP vs UDP

TCP is recorded delivery: it checks everything arrived, in order, and resends anything lost. UDP is shouting across a room: fast, no checking, and if a word gets lost, tough.

TCPUDP
ConnectionSets one up first (handshake)None. Just sends.
Reliable?Yes. Resends lost data, keeps order.No guarantees.

The TCP three-way handshake

  1. SYNclient → server"I'd like to talk. Here's my starting sequence number."
  2. SYN-ACKserver → client"Got it. Here's mine."
  3. ACKclient → server"Got yours. We're connected." Data can now flow.

You'll see these flags constantly in Wireshark and in port scanners. A port that answers a SYN with SYN-ACK is open.

Why would a video call use UDP instead of TCP?

A late video frame is useless. It's better to drop it and show the next one than to pause everything while TCP resends it.

FundamentalsPorts

An IP address gets data to the right computer. A port number gets it to the right program on that computer. If the IP is a block of flats, the port is the flat number.

Ports run from 0 to 65535. Ports 0–1023 are the "well-known" ones. Learn the common ones below by heart; they come up everywhere.

Chapter 3 · Networking: addressing

AddressingIP addresses

An IP address is a device's postal address on a network. Part of it says which street (the network) and part says which house (the host).

An IPv4 address is 32 bits, written as four numbers from 0 to 255 separated by dots, for example 192.168.1.10. Each of those four numbers is called an octet because it's 8 bits.

Every address has two parts:

  • Network portion: shared by every device on the same network.
  • Host portion: unique to each device on that network.

Where the split happens is set by the subnet mask, which is coming up shortly. First, you need binary.

AddressingBinary, the bit nobody wants to learn

Computers only see 1s and 0s. Each octet is 8 switches. Each switch has a value, and you add up the ones that are switched on.

Bit8th7th6th5th4th3rd2nd1st
Value1286432168421
192 =11000000
168 =10101000

192 = 128 + 64. 168 = 128 + 32 + 8. All eight on = 255, which is why no octet goes higher.

So the full address 192.168.1.1 in binary is:

192.168.1.1 = 11000000.10101000.00000001.00000001
What is 10101010 in decimal?

128 + 32 + 8 + 2 = 170.

AddressingSubnets & subnet masks

A subnet is a smaller network carved out of a bigger one, like splitting an office into floors. The subnet mask is the ruler that marks where the "street" part of the address ends and the "house" part begins.

Why subnet?

  • Performance. Broadcast traffic stays inside its own subnet instead of flooding the whole network.
  • Security. You can put firewall rules (ACLs) between subnets, so the CCTV cameras can't talk to the finance PCs.
  • Organisation. Addresses are handed out in tidy, sensible blocks, and new subnets can be added as you grow.

How the mask works

A subnet mask is also 32 bits: a run of 1s (network) followed by a run of 0s (hosts). 255.255.255.0 means the first 24 bits are network, the last 8 are hosts.

To find the network an address belongs to, the computer does a logical AND: a bit only stays 1 if it's 1 in both the address and the mask.

IP address 11000000.10101000.00000001.00000001 192.168.1.1 Subnet mask 11111111.11111111.11111111.00000000 255.255.255.0 ─────────────────────────────────── AND result 11000000.10101000.00000001.00000000 192.168.1.0 ← the network address

Two addresses you can't use

In every subnet, the first address (host bits all 0) is the network address and the last (host bits all 1) is the broadcast address. So a subnet with 256 addresses has 254 usable host addresses.

Designing subnets

Start from how many hosts each subnet needs, add room to grow, then pick the smallest mask that fits. Think about the physical layout too: a separate subnet per building, floor or function is easier to secure and troubleshoot.

A PC is 10.0.5.77 with mask 255.255.255.0. What network is it on?

10.0.5.0. The mask keeps the first three octets and zeroes the last.

AddressingCIDR notation

CIDR is shorthand. Instead of writing 255.255.255.0 you write /24, meaning "the first 24 bits are the network". Bigger number after the slash = smaller network.

192.168.1.0/24 means network 192.168.1.0 with a 24-bit mask. CIDR (Classless Inter-Domain Routing) replaced the old fixed "Class A/B/C" system, so you can split networks at any bit, not just at the dots.

/27 gives 30 usable hosts. A /28 only gives 14.

AddressingPublic vs private addresses

Private addresses are for inside your home or office and can be reused by everyone. Public addresses are unique across the whole internet. Your router swaps between the two using NAT.

Private ranges (RFC 1918)

10.0.0.0 – 10.255.255.25510.0.0.0/8Large businesses

So what's public?

Simple: almost everything else. Any IPv4 address that isn't in one of the reserved ranges above is a public, internet-routable address, handed out by regional registries (RIPE NCC for Europe, ARIN for North America, and so on) to ISPs and organisations.

NAT

Your ISP gives your router one public address. Every device in your house has a private one. When your laptop browses the web, the router swaps the private source address for its public one, remembers which device asked, and swaps it back when the reply comes in. That's Network Address Translation.

try it · private vs public
$ ip addr                        # your private address
$ curl https://ifconfig.me       # your public address, as the internet sees it
Your laptop shows 169.254.33.12. What's wrong?

It couldn't get an address from DHCP, so it gave itself a link-local one. Check the cable or Wi-Fi, and check the DHCP server.

AddressingIPv6 in two minutes

IPv4 has about 4.3 billion addresses and we ran out. IPv6 has 128-bit addresses, which is enough to give every grain of sand its own network. It's already running on your phone.

An IPv6 address looks like 2001:0db8:0000:0000:0000:ff00:0042:8329. You can drop leading zeros and replace one run of zero groups with ::, giving 2001:db8::ff00:42:8329.

  • ::1 is loopback (like 127.0.0.1).
  • Addresses starting fe80:: are link-local.
  • Subnets are almost always /64.
  • There's no ARP; IPv6 uses Neighbor Discovery instead. No broadcast either.

Security note: many networks are carefully firewalled on IPv4 and wide open on IPv6 because nobody thought about it. Check both.

Chapter 3 · Networking: protocols

Protocols · UDP/TCP 53DNS

DNS is the internet's phone book. You type a name like example.com; DNS looks up the number (the IP address) so your computer knows where to go. Without it you'd have to memorise IP addresses for every site you use.

How names are structured

Read a domain name right to left, from most general to most specific:

www . example . com . │ │ │ └─ root (the invisible dot) │ │ └─ Top-Level Domain (TLD): .com, .org, .uk │ └─ Second-Level Domain: what people call "the domain" └─ subdomain / host

Domains are registered through registrars (GoDaddy, Namecheap and so on) under rules set by ICANN. The owner of example.com can then create as many subdomains as they like, such as mail.example.com or dev.app.example.com.

Who's involved

  • Resolver (recursive resolver): does the legwork on your behalf. Usually your ISP's, your router's, or a public one like 1.1.1.1 or 8.8.8.8.
  • Root servers: know where every TLD's servers are.
  • TLD servers: know which servers are authoritative for each domain in their TLD.
  • Authoritative name servers: hold the actual records for a domain and give the final answer.

A lookup, step by step

  1. You type www.example.comYour computer checks its own cache first, then asks its configured resolver.
  2. Resolver checks its cacheIf it already knows the answer (and it hasn't expired), it replies immediately. Done.
  3. Resolver asks a root server"Where's .com?" The root replies with the addresses of the .com TLD servers.
  4. Resolver asks the .com TLD server"Where's example.com?" It replies with example.com's authoritative name servers.
  5. Resolver asks the authoritative server"What's the A record for www.example.com?" It gets the IP address.
  6. Resolver answers you and caches itYour browser connects to that IP. The answer is kept for its TTL.

Caching and TTL

Every answer comes with a Time To Live in seconds. Until it runs out, resolvers reuse the cached answer instead of repeating the whole lookup. That's why DNS changes can take a while to "propagate".

Record types

RecordDoes
AName → IPv4 address
AAAAName → IPv6 address
CNAMEAlias: this name is really that other name
MXWhich servers receive email for the domain
NSWhich servers are authoritative for the domain
TXTFree text; used for SPF, DKIM, DMARC and domain verification
PTRReverse lookup: IP → name

Security

Classic DNS is unencrypted and unauthenticated, so it can be spied on and spoofed. DNSSEC adds digital signatures so you can prove an answer is genuine. DNS over HTTPS / TLS encrypts the lookups so others on the network can't read them.

try it · ask DNS yourself
$ nslookup example.com
$ dig example.com A
$ dig example.com MX
$ dig +trace example.com         # watch the root → TLD → authoritative walk
You change a website's IP, but some people still reach the old server. Why?

Resolvers cached the old A record and will keep using it until its TTL expires.

Protocols · UDP 67/68DHCP

When you join a network, DHCP automatically gives you an IP address, subnet mask, default gateway and DNS server. Without it, someone would have to type those into every device by hand.

DHCP works on a client/server model. The conversation has four steps, remembered as DORA:

  1. Discoverclient → everyone (broadcast 255.255.255.255)"I've just arrived and have no address. Any DHCP servers out there?"
  2. Offerserver → client"You can have 192.168.1.50, mask 255.255.255.0, gateway .1, DNS .1, for 24 hours."
  3. Requestclient → everyone"I'll take the offer from that server, please." Broadcast, so other servers know they weren't chosen.
  4. Acknowledgeserver → client"Confirmed. It's yours." The client configures itself.

Leases

Addresses are leased, not given forever. Around halfway through the lease the client asks to renew. If a device leaves and never renews, the address goes back into the pool for someone else. That's how a café with 50 addresses can serve hundreds of customers a day.

The moving parts

  • DHCP server: holds the pool of addresses (the scope) and the settings to hand out. Often your router; in a business, often a Windows server.
  • DHCP client: any device asking for an address: PCs, phones, printers, TVs.
  • DHCP relay: DHCP uses broadcasts, which don't cross routers. A relay agent on each subnet forwards requests to a central server.
  • Reservations: always give the same address to a specific MAC address. Handy for printers and servers.

DHCP has no authentication. Anyone can plug in a rogue DHCP server and hand out themselves as the gateway, putting their machine in the middle of everyone's traffic. Managed switches stop this with a feature called DHCP snooping.

try it · renew your lease
# Windows
> ipconfig /release
> ipconfig /renew
# Linux (NetworkManager)
$ nmcli connection down "Wired connection 1" && nmcli connection up "Wired connection 1"
What does DORA stand for?

Discover, Offer, Request, Acknowledge.

Protocols · Layer 2ARP

Inside a local network, frames are delivered by MAC address, not IP. ARP (Address Resolution Protocol) is how a device finds out "which MAC address owns this IP?" It shouts the question to everyone, and the owner answers.

  1. ARP request (broadcast)"Who has 192.168.1.1? Tell 192.168.1.50."
  2. ARP reply (unicast)"192.168.1.1 is at 3c:22:fb:9a:10:4e."
  3. Cache itThe answer goes in the ARP table for a few minutes so it doesn't need to ask again.

When you talk to something on another network, your PC ARPs for the default gateway's MAC, and the router takes it from there.

ARP trusts whatever reply it gets, even ones nobody asked for. An attacker on the same network can keep announcing "the gateway is at my MAC", and everyone's traffic flows through their machine. That's a classic man-in-the-middle attack. Defences: Dynamic ARP Inspection on managed switches, network segmentation, and encrypting everything (HTTPS, SSH) so intercepted traffic is useless.

try it · see your ARP table
$ ip neigh       # Linux
> arp -a         # Windows / macOS
Does ARP work across a router?

No. ARP is a broadcast and broadcasts stop at the router. It only works within one local network.

Protocols · TCP 445SMB

SMB (Server Message Block) is how Windows shares files and printers. When you open \\fileserver\shared, that's SMB. Linux and macOS speak it too (Samba).

  • Runs on TCP 445. Older setups also used NetBIOS on 137–139.
  • Versions: SMBv1 (ancient, dangerous), SMBv2, and SMBv3 (supports encryption; use this).
  • Access is controlled by share permissions plus file (NTFS) permissions. Users usually authenticate with their Windows/domain account.

Why attackers love it

  • EternalBlue (MS17-010): a flaw in SMBv1 that let attackers run code on unpatched Windows machines. In 2017 it powered WannaCry, which hit the NHS and organisations across the world, and NotPetya.
  • Open shares with "Everyone: Full control" leak data constantly.
  • SMB lets attackers move sideways between machines once they're inside a network.

Disable SMBv1. Never expose port 445 to the internet. Patch. Give shares the least access needed. Turn on SMB signing.

try it · your own lab only
# list shares on a machine you own
$ smbclient -L //192.168.1.20 -U yourname
# Windows: is SMBv1 still on?
> Get-SmbServerConfiguration | Select EnableSMB1Protocol
Which SMB version did EternalBlue exploit?

SMBv1. That's why the first fix is to turn it off.

Protocols · TCP 25 / 587 / 465SMTP

SMTP (Simple Mail Transfer Protocol) is how email is sent and passed between mail servers. Reading your email uses different protocols: IMAP or POP3.

Journey of an email

  1. You hit SendYour mail app hands the message to your provider's server over port 587 (or 465), after logging in.
  2. DNS MX lookupYour server looks up the MX record for the recipient's domain to find their mail server.
  3. Server to serverYour server delivers it to theirs over port 25.
  4. Recipient reads itTheir mail app fetches it with IMAP (143/993) or POP3 (110/995).

SMTP is a plain-text conversation. The commands are readable: EHLO, MAIL FROM, RCPT TO, DATA, QUIT.

The big flaw: anyone can claim to be anyone

SMTP was designed in 1982 for a friendly network. Nothing in the protocol checks the "From" address, which is why phishing emails can claim to be from your bank. Three DNS records fix this:

RecordSays
SPF"These servers are allowed to send mail for my domain."
DKIM"Mail from me is digitally signed. Here's the public key to check it."
DMARC"If a message fails SPF/DKIM, reject it (or quarantine it), and send me reports."
try it · check a domain's email security
$ dig example.com MX
$ dig example.com TXT              # look for v=spf1 ...
$ dig _dmarc.example.com TXT       # look for v=DMARC1 ...
A domain has no DMARC record. What does that mean for phishing?

Receiving servers have no instruction to reject mail that fakes that domain, so spoofed emails are far more likely to land in inboxes.

Protocols · TCP 80 / 443HTTP & HTTPS

HTTP is how browsers and web servers talk. The browser sends a request ("give me this page"), the server sends a response (the page, plus a status code). HTTPS is exactly the same conversation inside an encrypted TLS tunnel.

A real request and response

what actually goes over the wire
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Cookie: session=abc123

---- response ----
HTTP/1.1 200 OK
Content-Type: text/html
Set-Cookie: session=abc123; Secure; HttpOnly

<html>...

Methods

GET fetches. POST sends data (forms, logins). PUT replaces, PATCH updates, DELETE deletes. HEAD is a GET without the body.

Status codes

RangeMeaningCommon ones
2xxSuccess200 OK, 201 Created
3xxGo somewhere else301 Moved Permanently, 302 Found
4xxYou got it wrong401 Unauthorized, 403 Forbidden, 404 Not Found

Stateless, so cookies

HTTP forgets you between requests. Websites remember you're logged in by giving your browser a cookie that it sends back every time. Steal someone's session cookie and you're logged in as them, which is why cookies should be marked Secure and HttpOnly.

HTTPS

The padlock means the connection is encrypted and the server proved its identity with a certificate. It does not mean the site is trustworthy. Phishing sites have padlocks too.

try it
$ curl -I https://example.com       # just the response headers
$ curl -v https://example.com       # everything, including the TLS handshake

Or press F12 in your browser and open the Network tab, then reload any page.

You get a 403. Is the page missing?

No. 403 means it exists but you're not allowed to see it. Missing is 404.

Defend & observe

SecurityFirewalls

A firewall is a bouncer with a list. Every piece of traffic gets checked against the rules, top to bottom. If it matches an "allow" it gets in. If nothing matches, the last rule should be "deny everything else".

Types

  • Packet filter (stateless): checks each packet on its own: source, destination, port, protocol. Fast and dumb.
  • Stateful: remembers connections. If you started a conversation, it lets the replies back in automatically. Most firewalls today.
  • Next-generation (NGFW): understands applications and users, not just ports. Can block "BitTorrent" even if it hides on port 443.
  • Web Application Firewall (WAF): sits in front of websites and blocks attacks like SQL injection.
  • Host-based: runs on the computer itself. Windows Defender Firewall, ufw/nftables on Linux.

Reading a rule set

#ActionFromToPortWhy
1ALLOWAnyWeb server443Public website
2ALLOWIT subnetServers22Admins can SSH
3DENYGuest Wi-FiInternalAnyGuests get internet only
4DENYAnyAnyAnyDefault deny

Order matters. Most firewalls stop at the first match, so a broad "allow" near the top can make everything below it pointless.

Don't forget egress (outbound) rules. Malware needs to phone home. A server that only ever needs to talk to its database shouldn't be able to reach the whole internet.

try it · simple Linux host firewall
$ sudo ufw default deny incoming
$ sudo ufw default allow outgoing
$ sudo ufw allow 22/tcp
$ sudo ufw enable
$ sudo ufw status numbered
Rule 1 is "ALLOW any → any port 80". Rule 2 is "DENY 10.0.0.5 → any". Can 10.0.0.5 browse on port 80?

Yes. Rule 1 matches first and the firewall stops looking. Put specific denies above broad allows.

SkillsNetwork analysis

Network analysis means looking at the actual traffic on the wire, packet by packet. It's how you troubleshoot, how you spot attackers, and how you really learn everything on this page. Reading about DHCP is fine. Watching DORA happen live is how it sticks.

The tools

  • Wireshark: the graphical packet analyser. Free. Install it today.
  • tcpdump: command-line capture. On every Linux box and great on servers.
  • Nmap: discovers hosts and open ports. Read its free online book.
  • ping / traceroute / mtr: is it up, and which way does the traffic go?

$ traceroute example.com             # Windows: tracert example.com
$ nmap -sn 192.168.1.0/24            # which devices are on MY home network?

Capturing traffic or port-scanning networks you don't own or have written permission to test is illegal in the UK (Computer Misuse Act 1990) and most other places. That includes work, school, and the coffee-shop Wi-Fi. Your own home network and your own virtual lab are fine.

Wireless is just networking where the cable is replaced by radio. The catch: radio goes everywhere, through walls and into the car park, so anyone nearby can hear it. Encryption isn't optional.

  • 5 GHz: faster, more channels, shorter range.
  • 6 GHz (Wi-Fi 6E / 7): very fast, very clean, short range.

ICS / OT · Industrial Control Systems

Read this firstAn introduction to ICS, and why you should NEVER attempt to hack it

Industrial Control Systems (ICS), also called Operational Technology (OT), are the computers that run physical things: water treatment, power grids, factories, gas pipelines, traffic lights, hospital systems. When IT breaks, you lose data. When OT breaks, things explode, flood, poison or kill people.

Why "just having a look" is a terrible idea

  • It's fragile. A lot of OT kit is 20–30 years old and was never designed to see unexpected traffic. Simple network scans have been known to crash controllers and stop production lines.
  • Safety comes first, security second. In IT the priority is confidentiality. In OT it's keeping the process running safely. You can't just "reboot to fix it" when the process is a chemical reactor.
  • It's critical national infrastructure. Attacks on it are treated as national security matters. Expect serious prison time, not a slap on the wrist.
  • The protocols have no security. Many will accept a "stop" or "open valve" command from anyone who can reach them. It's not clever to send one; it's reckless.

The real incidents you should read about

  • Stuxnet (discovered 2010): malware that damaged Iranian uranium centrifuges by quietly changing PLC logic while showing operators normal readings.
  • Ukraine power grid (2015, 2016): attackers remotely opened breakers and cut power to around 225,000 people.
  • Triton / Trisis (2017): malware that targeted the safety systems of a petrochemical plant, the last line of defence that stops explosions.

Learn ICS with simulators and your own bench kit. Never touch a real system you find online. Good free starting points: OpenPLC (a free PLC you can run on a Raspberry Pi or PC), ModbusPal or pymodbus (Modbus simulators), and the free ICS resources from CISA.

ICS / OTShodan

Google indexes web pages. Shodan indexes devices. It constantly scans the internet and records what answers: webcams, routers, servers, and, worryingly, industrial controllers that should never have been online.

Shodan stores each device's banner: the text a service sends back when you connect, which often reveals the product, version and sometimes the organisation.

Example searches

SearchFinds
port:502Devices answering on Modbus TCP
port:3389 country:GBExposed Remote Desktop in the UK
product:"Apache httpd"Apache web servers
net:203.0.113.0/24Everything Shodan knows about one address range

Defenders use Shodan to check what their own organisation is accidentally exposing. Researchers use it to measure how many vulnerable devices exist. Shodan does the scanning; you're reading its results.

Reading Shodan results is legal. Connecting to what you find is not. Logging into an exposed HMI, trying default passwords, or sending a single Modbus command to a device you don't own is unauthorised access. If you find something genuinely dangerous, report it to your national CERT (in the UK, the NCSC) and walk away.

Search your own home's public IP on Shodan. What's the best result?

Nothing at all. If something shows up, you have a port open to the internet you probably didn't intend.

ICS / OTThe Purdue Model

The Purdue Model (from Purdue University, 1990s) splits an industrial organisation into levels, from the physical machinery at the bottom to email and the internet at the top. The point is separation: each level should only talk to the levels next to it, so someone who phishes an office PC can't reach the valves.

5
Enterprise network

Corporate IT, internet access, cloud services.

4
Business planning & logistics

ERP, email, office PCs, scheduling.

3.5
Industrial DMZ

The buffer zone. Nothing passes straight from IT to OT; traffic stops here (patch servers, jump hosts, data replicas).

3
Site operations

Historians (process databases), MES, site-wide servers.

2
Supervisory control

HMIs and SCADA servers. Where operators watch and control.

1
Basic control

PLCs, RTUs, safety controllers. Making decisions in milliseconds.

0
Physical process

Sensors, motors, pumps, valves. The actual stuff.

Levels 0–3 are OT. Levels 4–5 are IT. The 3.5 DMZ between them is where most of the security effort goes.

In real life the neat layers are often blurred by remote access for vendors, cloud monitoring and "temporary" connections that became permanent. That's exactly where attackers get in.

An attacker phishes someone in accounts. Which Purdue level are they on, and what should stop them going further?

Level 4. The industrial DMZ (3.5) and its firewalls should stop them reaching levels 3 and below.

ICS / OT · Level 1PLCs

A PLC (Programmable Logic Controller) is a tough little computer that controls machinery. It reads sensors, runs a simple program, and switches motors and valves on or off, over and over, thousands of times a minute, for years without a reboot.

The scan cycle

  1. Read inputsCheck every sensor: is the tank full? Is the guard door shut? Is the button pressed?
  2. Run the programWork through the logic using those input values.
  3. Write outputsTurn pumps, motors, lights and valves on or off.
  4. RepeatTypically every few milliseconds, forever.

Ladder logic

PLCs are commonly programmed in ladder logic, which looks like an electrical wiring diagram because it was designed for electricians. Other languages (function block, structured text) are defined in the IEC 61131-3 standard.

Start Stop Guard door ──┤ ├──┬────┤/├────────┤ ├──────────( Motor )── │ Motor │ ──┤ ├──┘ "Run the motor if Start is pressed (or it's already running), and Stop is NOT pressed, and the guard door is closed."

Big names: Siemens (S7), Rockwell / Allen-Bradley, Schneider Electric (Modicon), Mitsubishi, Omron.

Many PLCs accept new programs over the network with no password. Change the logic and you change what the machine physically does. That's what Stuxnet did.

Learn safely: install OpenPLC on a spare PC or a Raspberry Pi and write ladder logic to light an LED.

ICS / OT · Level 2SCADA

SCADA (Supervisory Control And Data Acquisition) is the system that lets a control room watch and manage equipment spread over a large area, like every pumping station in a county's water network, from one place.

The pieces

  • Field devices: PLCs and RTUs (Remote Terminal Units) out at each site.
  • Communications: radio, mobile data, leased lines, fibre, sometimes satellite.
  • SCADA server (master station): polls the field devices and collects the data.
  • HMI: the screens operators use.
  • Historian: a database storing every reading, for trends and investigations.

SCADA vs DCS

A DCS (Distributed Control System) does a similar job but inside one plant, like a refinery. SCADA covers wide areas: pipelines, grids, water networks. People often say "SCADA" to mean all industrial control. Now you know the difference.

ICS / OT · TCP 502Modbus

Modbus is one of the oldest and most common industrial protocols. A controller asks a device "what's in register 5?" or tells it "set coil 3 to ON". It's simple, it's everywhere, and it has no security whatsoever.

  • Created by Modicon in 1979. Still in use everywhere.
  • Modbus RTU runs over serial cables (RS-485). Modbus TCP runs over Ethernet on port 502.
  • One side asks (client / master), the other answers (server / slave). Each device has a unit ID.

The data model

TypeSizeAccessExample
Coils1 bitRead / writePump on/off
Discrete inputs1 bitRead onlyDoor closed sensor
Input registers16 bitRead onlyTemperature reading
Holding registers16 bitRead / writeTemperature set point

Common function codes

CodeDoes
01Read coils
03Read holding registers
04Read input registers
05Write single coil
06Write single register
16 (0x10)Write multiple registers

There's no login, no encryption and no check of who's asking. Anyone who can reach port 502 can read every value and write new ones. Exposing Modbus to the internet is effectively handing out the controls. Defences: keep it isolated (see Purdue), firewall it, and monitor for unexpected write commands.

$ pip install pymodbus
# run one of pymodbus's example servers on 127.0.0.1:5020,
# then point a Modbus client at it and open Wireshark with filter: mbtcp
You want to change a temperature set point. Which data type and function code?

A holding register, written with function code 06 (or 16 for several at once).

ICS / OT · Level 2HMI: Human Machine Interface

The HMI is the screen operators use to see and control the process: tank levels, pump status, alarms, and buttons to start and stop things. It can be a touch panel on a machine or a wall of monitors in a control room.

  • Shows live values from PLCs and the SCADA server, usually as diagrams of the plant.
  • Raises alarms when values go out of range.
  • Sends operator commands back down to the PLCs.

Why HMIs are a weak spot

  • Often old Windows PCs that can't be patched without breaking vendor support.
  • Shared operator logins, or default passwords that were never changed.
  • Remote access tools installed "temporarily" for vendors.
  • Web-based HMIs sometimes end up directly on the internet, where Shodan finds them.

Remember Stuxnet: the attackers made the HMI show normal values while the centrifuges were being damaged. Operators can only trust what the screen tells them.

ICS / OT · VehiclesCAN bus

CAN (Controller Area Network) is the network inside your car. Engine, brakes, airbags, windows and dashboard all chat over a pair of twisted wires. It's also used in tractors, lifts, medical devices and factory equipment.

  • Developed by Bosch in the 1980s. In practically every car since the early 2000s.
  • Two wires: CAN-High and CAN-Low. Every message goes to every device: it's a broadcast bus.
  • Each message has an ID and up to 8 bytes of data (64 bytes with the newer CAN FD).
  • The ID also sets priority: if two devices talk at once, the lower ID wins.
  • The OBD-II port under your dashboard gives access to it, for diagnostics.
ID DLC DATA 0x244 8 00 00 00 01 3A 00 00 00 ← e.g. a speed value (meaning varies by maker)

There's no authentication: any device on the bus can send any message, and the others believe it. Researchers have shown remote attacks reaching steering and brakes. Never experiment on a vehicle that will be driven, and never on public roads.

try it · a virtual CAN bus on Linux, no car needed
$ sudo apt install can-utils
$ sudo modprobe vcan
$ sudo ip link add dev vcan0 type vcan && sudo ip link set up vcan0
$ candump vcan0 &               # listen
$ cansend vcan0 244#0000000132   # send a frame

For a full simulated dashboard to practise on, search for ICSim (Instrument Cluster Simulator).

ICS / OT · RadioRadio frequencies

Every wireless thing, from car key fobs and doorbells to pagers, Wi-Fi and SCADA telemetry, is a radio sending signals at a particular frequency. With a cheap Software Defined Radio you can see and decode a surprising amount of it.

The basics

  • Frequency is measured in hertz (Hz): cycles per second. kHz = thousand, MHz = million, GHz = billion.
  • Lower frequencies travel further and through walls but carry less data. Higher frequencies carry more data over shorter distances.
  • Modulation is how data is put onto the wave: by changing its amplitude (AM/ASK), frequency (FM/FSK) or phase.

Frequencies you'll meet

FrequencyWhat's there
125 kHzOld RFID access cards and fobs
13.56 MHzNFC, contactless bank cards, newer access cards
87.5–108 MHzFM broadcast radio
315 / 433 MHzCar keys (US / EU), garage doors, wireless doorbells, weather stations
868 / 915 MHzLoRa, smart meters, alarm sensors (EU / US)
1090 MHzADS-B: aircraft broadcasting their positions
2.4 / 5 GHzWi-Fi, Bluetooth, Zigbee

Tools

  • RTL-SDR dongle (about £30): receive only, roughly 24 MHz–1.7 GHz. The perfect first toy. Track planes with ADS-B, decode weather stations.
  • HackRF / Flipper Zero: can also transmit. That's where the law gets serious.
  • Software: SDR++, GQRX, Universal Radio Hacker (URH), rtl_433.

Transmitting without a licence outside the permitted bands and power limits is illegal (in the UK, regulated by Ofcom under the Wireless Telegraphy Act 2006). Jamming is illegal everywhere. In the UK, even listening to and using the content of some transmissions not meant for you is an offence. Check your own country's rules. Receiving public broadcasts, ADS-B, and your own devices is the safe place to start.

Physical accessHID: USB on steroids

HID means Human Interface Device: keyboards and mice. Computers trust any keyboard you plug in, instantly, no questions asked. A small gadget that pretends to be a keyboard can type a thousand characters a second, so it can open a terminal and run commands faster than you can blink.

How it works

  1. Plug inThe device tells the computer "I'm a keyboard." No driver warning, no permission prompt.
  2. Wait a momentA short delay while the operating system sets it up.
  3. TypeIt fires off a pre-written script of keystrokes: open a terminal, download something, run it, close the window.

Known examples

  • USB Rubber Ducky (Hak5): the original. Scripts are written in "DuckyScript".
  • Flipper Zero BadUSB and DIY builds on a Raspberry Pi Pico: the same idea for a few pounds.
  • O.MG cable: the attack hardware hidden inside what looks like a normal charging cable.
  • BadUSB (the research): showed that ordinary USB sticks can have their firmware rewritten to behave like keyboards.

Lock your screen whenever you walk away (Win+L, Ctrl+Cmd+Q). Never plug in a USB stick or cable you found or were "given". Businesses can use USB device control to allow only approved devices, and disable unused ports. Physical access beats most security, so protect it.

Learn safely: build a Pi Pico HID device and point it at your own spare laptop with a harmless script that opens Notepad and types "hello".

Why doesn't antivirus stop a HID attack when it's plugged in?

To the computer it's just a keyboard, and keyboards are trusted. Antivirus may catch what the typed commands download, but not the typing itself.
